# Админ-панель портала мастер-плана Твери — инструкция

Документ для владельца сайта (`2KAd` / Евгений Зоткин). Описывает как войти в
админку, что она показывает, где лежат данные и какие есть подводные камни
после переделки опроса в анонимный режим.

> **Снимок состояния:** август 2026. Описывает код в `tver-masterplan/admin.html`,
> `assets/js/modules/portal-admin.js`, `api/tver-portal/index.php`.

---

## 1. Где находится и как войти

**URL:** `https://urban2kad.ru/tver-masterplan/admin.html`
(открывать только в браузере; поисковикам закрыто через `noindex`).

**Токен администратора** сейчас зашит прямо в PHP:

```
tver-admin-SJotS1vfiImhTCPpIX-bXd6CIu8ZzrnV
```

Файл: `public_html/api/.htaccess`, строка
`SetEnv TVER_PORTAL_ADMIN_API_TOKEN "..."`.
**Рекомендация по безопасности:** перенести токен в переменную окружения
сервера и читать через `getenv()` — сейчас он виден всем, у кого есть FTP.

### Процесс входа

1. Открыть `admin.html`.
2. Ввести токен в поле «Служебный токен доступа».
3. Нажать «Загрузить данные».
4. Токен сохраняется в `localStorage` под ключом `tverPortalAdminToken` —
   в следующий раз вводить не нужно, пока не очистишь storage браузера.

Все запросы к защищённым эндпоинтам идут с заголовком
`Authorization: Bearer <token>`. Невалидный токен → 401.

## 2. Архитектура «под капотом»

```
┌─ Браузер модератора
│   └─ admin.html (UI)
│      └─ assets/js/modules/portal-admin.js (логика)
│         └─ fetch с Bearer-токеном
│
└─ Сервер (Apache + PHP)
   ├─ public_html/tver-masterplan/admin.html
   ├─ public_html/api/.htaccess
   │     └─ SetEnv TVER_PORTAL_ADMIN_API_TOKEN "..."
   │     └─ Rewrite: всё под /api/tver-portal → index.php
   └─ public_html/api/tver-portal/
      ├─ index.php (878 строк, всё API в одном файле)
      ├─ data/
      │   ├─ .htaccess  (Require all denied)
      │   └─ store.json ← создаётся автоматически при первой записи
      └─ uploads/      (для картинок к идеям)
```

### Хранилище

Не MySQL/PostgreSQL, а **один JSON-файл**:
`public_html/api/tver-portal/data/store.json`. Защищён `.htaccess` от прямого
скачивания через веб. Бэкапится просто: скачать через FTP.

Структура `store.json`:

```jsonc
{
  "counters": { "survey": 0, "idea": 0 },
  "surveys":      [ /* массив объектов с fullName, email, ageGroup, district,
                       topics, satisfaction, priorityProject, comment,
                       consent, ipHash, userAgent, createdAt и т.д. */ ],
  "ideas":        [ /* id, title, description, theme, координаты, адрес,
                       authorName, authorEmail, status, likesCount, и т.д. */ ],
  "personalDataRequests": [ /* 152-ФЗ запросы: fullName, email, phone,
                                requestType, message, status, и т.д. */ ],
  "moderationLog":      [ /* история модерации: ideaId, moderatorId, action,
                              fromStatus, toStatus, comment, at */ ]
}
```

Срок хранения: `365 дней` (зашит в PHP, `$config['retentionDays']`).
Просроченные записи PHP-фильтр `prune()` отрезает автоматически при каждом
обращении к `store.json`.

### Поток данных

| Действие пользователя | Куда идёт | Что сохраняется |
|-----------------------|-----------|-----------------|
| Отправка **анкеты** (старая версия с ФИО) | `POST /api/tver-portal/surveys` | `surveys[]` |
| Отправка **идеи** на карте | `POST /api/tver-portal/ideas` | `ideas[]` (авто-`status: approved`) |
| **Запрос по 152-ФЗ** | `POST /api/tver-portal/personal-data/requests` | `personalDataRequests[]` |
| **Модерация** (админ) | `PATCH /api/tver-portal/moderation/ideas/{id}` | `ideas[].status` + запись в `moderationLog` |
| **Запрос ПДн** (админ) | `PATCH /api/tver-portal/personal-data/requests/{id}` | `personalDataRequests[].status` |

## 4. Секции админки (сверху вниз)

### 4.1. «Доступ модератора»

Поле ввода токена + кнопка «Загрузить данные». После загрузки токен живёт
в `localStorage`. Очистить: devtools → Application → Local Storage → удалить
`tverPortalAdminToken`.

### 4.2. «Аналитика» (8 метрик)

Источник: `GET /api/tver-portal/analytics`. Поля:

| Метрика | Что показывает |
|---------|----------------|
| `Анкет всего` | `count(surveys)` |
| `Идей всего` | `count(ideas)` |
| `Идеи по статусам` | разбивка по `status` (approved / pending / rejected) |
| `Одобренные по темам` | разбивка approved-идей по `theme` |
| `Запросы ПДн` | `count(personalDataRequests)` |
| `Статусы запросов ПДн` | разбивка по статусам |
| `Версия политики` | `2026-05-19` (из PHP) |
| `Срок хранения` | `365 дней` (из PHP) |

> **Важно:** `GET /api/tver-portal/analytics` **не требует токена** — это
> публичный эндпоинт. Если не хочешь показывать счётчики всему миру, добавь
> `requireAdmin(...)` в PHP рядом с `if ($route === 'analytics' ...)`.

### Про токен и заголовок (нюанс из реальной проверки)

При проверке из `curl`/`Terminal` через nginx-frontend:

```bash
# ❌ возвращает 401 — заголовок Authorization режется на internal rewrite
curl -H "Authorization: Bearer $TOKEN" https://urban2kad.ru/api/tver-portal/surveys

# ✅ работает — fallback-заголовок, который PHP поддерживает
curl -H "X-Admin-Token: $TOKEN" https://urban2kad.ru/api/tver-portal/surveys
```

В **браузере** админка работает, потому что `fetch` отправляет оба заголовка,
или потому что nginx пропускает `Authorization` только в определённых условиях.
Через `curl` безопаснее использовать `X-Admin-Token` напрямую.

### 4.3. «Опрос горожан: дашборд результатов»

Источник: `GET /api/tver-portal/surveys` (нужен токен).

Содержит:

- **Кнопки экспорта:**
  - «Скачать анкеты CSV» — `;`-разделитель, UTF-8 с BOM (нормально открывается
    в русском Excel). Колонки: `ID, Дата и время, ФИО, Email, Возрастная
    группа, Район, Темы, Оценка удовлетворённости, Приоритетный проект,
    Комментарий`.
  - «Скачать анкеты JSON» — сырой массив `surveys[]`.
- **Фильтры** (применяются и к дашборду, и к экспорту):
  - дата с / дата по
  - район
  - возрастная группа
  - кнопка «Сбросить»
- **5 KPI:** всего анкет, средняя оценка, с email, с приоритетным проектом,
  территорий участия.
- **4 гистограммы:** возраст, район, темы, удовлетворённость.
- **«Последние анкеты»** — лента из 12 последних записей.

> **⚠️ После моей переделки:** форма стала анонимной и перестала слать данные
> на сервер. Исторические анкеты (если есть) всё ещё можно посмотреть и
> выгрузить. Новых — не будет, пока не вернёшь POST в `portal-survey.js`.

### 4.4. «Модерация идей: очередь публикации»

Источник: `GET /api/tver-portal/moderation/ideas?limit=200` (нужен токен).

Для каждой идеи карточка с заголовком, описанием, адресом, автором, лайками
и тремя кнопками:

- **«Опубликовать»** → `status: 'approved'`
- **«На доработку»** → `status: 'needs_revision'`
- **«Отклонить»** → `status: 'rejected'`

Все три пишут в `moderationLog[]` (кто, что, когда, опциональный комментарий).

> **Замечание:** сейчас **все новые идеи публикуются автоматически** —
> PHP выставляет `status: 'approved'` и `moderatedBy: 'system-auto'` при POST.
> То есть очередь пустая, пока кто-то не сменит статус руками или не появится
> флаг «нужна проверка». Если хочешь, чтобы идеи шли через премодерацию —
> нужно править `index.php` (убрать `'status' => 'approved'` из POST-ветки).

### 4.5. «Запросы субъектов ПДн: обработка обращений»

Источник: `GET /api/tver-portal/personal-data/requests?limit=200` (нужен токен).

Обязательно по 152-ФЗ — отрабатывать в срок. Карточка с ФИО, типом запроса,
текстом, контактами (email/телефон) и тремя кнопками:

- **«В работу»** → `status: 'in_progress'`
- **«Исполнено»** → `status: 'completed'`
- **«Отклонено»** → `status: 'rejected'`

Срок ответа по закону — **30 дней** с момента получения. Сейчас из-за анонимного
опроса эта очередь тоже будет пустой, пока кто-то реально не пришлёт
запрос через `privacy.html`.

## 5. Экспорт и резервное копирование

### Экспорт из админки (только анкеты)

Кнопки «Скачать CSV/JSON» в дашборде. Выгрузка учитывает **текущие фильтры**:
если выставлен район — в файл попадут только анкеты по этому району.

CSV: `;`-разделитель, UTF-8 c BOM. Имена файлов:
`tver-surveys-{scope}-{YYYY-MM-DD}.{csv|json}`,
где `scope` — `all` или `filtered-{filters}`.

### Бэкап всего `store.json` (рекомендуется)

```bash
/opt/homebrew/bin/lftp -u cl58936 vh318.timeweb.ru -e \
  "get /urban2kad.ru/public_html/api/tver-portal/data/store.json \
   -o ./backups/tver-portal-$(date +%F).json; bye"
```

Или руками через FTP-клиент: скачать
`public_html/api/tver-portal/data/store.json` (несмотря на `.htaccess deny from
all`, через FTP доступ есть — защита работает только на веб-уровне).

**Частота:** раз в неделю или после крупных изменений. Файл маленький, можно
просто архивировать.

## 6. Прямой доступ к API (curl)

Для интеграций, отладки или своих скриптов.

### Аналитика (без токена)

```bash
curl -s https://urban2kad.ru/api/tver-portal/analytics | jq
```

### Список анкет (нужен токен)

```bash
TOKEN="tver-admin-SJotS1vfiImhTCPpIX-bXd6CIu8ZzrnV"
curl -s -H "Authorization: Bearer $TOKEN" \
  https://urban2kad.ru/api/tver-portal/surveys | jq '.data | length'
```

### Сменить статус идеи вручную

```bash
IDEA=42
curl -s -X PATCH \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action":"rejected","comment":"Не относится к Твери"}' \
  https://urban2kad.ru/api/tver-portal/moderation/ideas/$IDEA
```

Доступные `action`: `approved` / `needs_revision` / `rejected`.

### Закрыть запрос ПДн

```bash
REQ=7
curl -s -X PATCH \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action":"completed","comment":"Данные отправлены на email"}' \
  https://urban2kad.ru/api/tver-portal/personal-data/requests/$REQ
```

Доступные `action`: `in_progress` / `completed` / `rejected`.

## 7. Безопасность — что стоит поправить

| Риск | Где | Что сделать |
|------|-----|-------------|
| Токен в открытом виде | `api/.htaccess` | Перенести в env-var: `SetEnv TVER_PORTAL_ADMIN_API_TOKEN` убрать, читать через `getenv()` в PHP. Перегенерировать токен после переноса. |
| Аналитика публична | `GET /api/tver-portal/analytics` (нет `requireAdmin`) | Добавить проверку токена, если счётчики чувствительные. |
| Endpoints POST без rate-limit | `POST /surveys`, `/ideas`, `/personal-data/requests` | Добавить простую защиту (по cookie/IP), иначе можно зафлудить `store.json`. Honeypot уже есть (поле `website`), но без серверной проверки. |
| Данные ПДн лежат одним файлом | `data/store.json` | Если хостинг позволяет — переехать на MySQL/PostgreSQL. Сейчас `store.json` лежит плоско, бэкап — вручную. |
| Анонимный опрос не отправляет данные | `assets/js/modules/portal-survey.js` (submit handler) | Осознанное решение. Если в будущем захочешь собирать анонимную статистику — есть смысл завести отдельный `/api/tver-portal/anon-surveys` без полей ФИО/email/consent. PHP-валидатор в `index.php` тоже придётся ослабить. |
